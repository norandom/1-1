- Rows 1.1–1.5, 6.1–6.3, 12.6 classified by task 3.1 (persistence domain); rows 2.1–2.5 appended by task 3.2 (session-actor domain, seams below); rows 3.1–3.6 + the 12.9 input-domain slice appended by task 3.3 (input/display controls); rows 4.1–4.3 + 5.1–5.4 appended by task 3.4 (shell/render domain); rows 7.1–7.5 + the perf/interop evidence appended by task 3.5 (baseline integration), completing the "every Req 1–7" classification.
- Task 3.2 seams (narrow, behavior-unchanged): `ConnectFn` (`src-tauri/src/rdp/session.rs` L96–115) indirection at the RDP connection boundary — production default is `real_connect()` = `attempt_rdp_connection`; `SessionEventSink` (session.rs L153–192) closure seam at the outbound frontend-event boundary — production `app()` delegates to `tauri::AppHandle::emit` with identical JSON payloads. `SessionManager::create_session` keeps its production signature and delegates to `pub(crate) create_session_with_transport` (session.rs L1147). The frame channel needed **no seam**: `tauri::ipc::Channel::new` is public, so scripted callbacks drive the production loss model ("frame packet send failure = connection lost", session.rs `send_frame_packet` L324). No actor framework, no new runtime deps beyond the tokio `test-util` dev-feature (tokio "full" does not include it; added in `[dev-dependencies]`).
- Task 3.3 seams (narrow, behavior-unchanged): `encode_keyboard_fastpath_event` / `encode_mouse_fastpath_event` (`src-tauri/src/rdp/session.rs`, pure moves of the inline FastPath input encoding out of `run_real_session_loop`) — the loop's writer is the concrete `TlsFramed` TLS stream type, so the encode functions are the deepest deterministic seam; wire-level verification stays a real-server check (12.9). TypeScript pure moves: `normalizeWheelDelta` + `ctrlAltDelSequence` into `src/lib/input-mapper.ts` (from `useRdpSession.sendWheel` / `SessionView.handleCtrlAltDel`) and `createTrailingResizeScheduler` into `src/lib/resize-debounce.ts` (from `SessionView.handleResize`); production call sites were rewired to the extracted functions with identical semantics (including the stale-session-id debounce edge and the absence of unmount cancellation, both preserved as-is).
- Task 3.4 seams (narrow, behavior-unchanged): TS pure moves into `src/lib/` with production call sites rewired — `fitSurfaceToContainer`/`unionDirtyRect`/`compositeFrameRects` (from `SessionCanvas.tsx`'s fit math, dirty union and frame-subscription rect loop), `formatBandwidth`/`fpsLevel`/`latencyLevel` (from `PerformanceHUD.tsx`), `resolveTheme`/`nextThemeInCycle` (from `useTheme.ts`), `buildStatusBarText`/`sessionCountLabel` (from `StatusBar.tsx`), `SHORTCUT_SECTIONS` (from `ShortcutOverlay.tsx`), plus `export defaultSettings` in `settingsStore.ts`. Rust: `append_rect_pixels` extracted verbatim from `encode_image_update_packet` (`frame_transport.rs`) so stride handling is testable with synthetic data (`DecodedImage` exposes no data setter). No DOM, React or GPU behavior changed.
- Task 3.5 seams (narrow, behavior-unchanged): `build_connector_config` (`src-tauri/src/rdp/client.rs`) is now `pub(crate)` so the baseline harnesses reuse the production connector config verbatim; everything else lives in the new `src-tauri/src/rdp/baseline.rs` (deterministic fixture helpers + unit tests, the two `#[ignore]`d harnesses) and `scripts/Invoke-Baseline.ps1` (env loading without echo, CPU/WS sampling, redaction self-check). No production code path changed.
- Criterion 4.4 is a future delta and **not** an old-stack gate (per Req 12.6).
- Defect IDs `B3-n` are pinned by defect-marked tests (suffix `_defect_b3_n`) that document current behavior **without approving or freezing** it; fixes belong to later task groups and require regression tests first (Req 13.2). `D2` is the pre-existing defect from research.md.
- All tests are deterministic: tempfile isolation, serde_json fixtures, loopback-only sockets, scripted keyring builders (keyring's public `set_default_credential_builder` hook — no OS keyring, no env overrides, no load-bearing sleeps). Task 3.4 note: the SharedFrame wake test (`wait_for_frame_parks_until_mark_dirty_wakes_it`) contains one 20 ms park-hint sleep whose outcome is timing-independent via the dirty-flag fast path (a wake that fires before the park still returns through `dirty.load()`); the `wait_for_frame_returns_immediately_when_dirty` assertion uses a generous 1 s bound around an immediate return. Req 12.7 isolation: tests touch only their tempfile scopes.
