# Windows DirectComposition probe: results, 21 November 2026

Machine: the maintainer's Windows 11 Pro workstation (build 26200), AMD Radeon 890M (integrated, driver 32.0.32015.12012), wgpu 24 on DX12, display scale 100% at about 100 Hz. Window 1600×1000, hole 1600×920 physical pixels. Measured with `scripts/windows/Measure-AppCpu.ps1`, 20 s each, `PROBE_UPLOAD=full` (the whole frame uploaded every frame, the worst case).

## It composes as hoped

The screenshot taken during the run shows the pattern in the hole, the page's header and footer around it, and the page's floating overlay (a rounded, semi-transparent box with a clock) drawn **above** the layer. A non-topmost DirectComposition target on the main window sits below WebView2's child windows; with the window transparent (`"transparent": true`, which also makes WebView2's default background transparent) the hole shows the layer. Clicks go to the web view, which covers the whole client area.

## Cost

| Mode | Frame rate | Main thread | Probe process | WebView2 renderer | WebView2 GPU | Whole app |
| --- | --- | --- | --- | --- | --- | --- |
| Layer (DirectComposition) | 101 fps | 0.2% | 8.6% | 0.4% | 0.2% | **9.9%** |
| Canvas (`putImageData`) | 100 fps | 0.0% | 0.0% | 13.7% | 30.3% | **44.0%** |

Percent of one core. The layer's render thread spends 0.6–0.7 ms of CPU per frame, almost all of it the 5.9 MB `write_texture` copy.

The canvas costs 4.4 times the layer **before** any IPC: in 1-1 each frame also travels through a Tauri channel, which on Windows means a WebView2 resource request served by the browser process and answered on the main thread ([profiling](../../docs/profiling-windows.md): 68% of one core for a window drag, 19% of it in the browser process and 14% on the main thread).

## For the spec

- Requirement 5.3's rule is met on Windows: the canvas costs more than twice the layer, so the spec is extended with a Windows `NativeLayer`.
- The route needs no wry fork: `CreateTargetForHwnd(hwnd, false)` on the window `tauri` creates, one visual per session, wgpu's `CompositionVisual` surface.
- Every DirectComposition call (configure's `SetContent`, offsets, clip, `Commit`) belongs on the main thread; the render thread only acquires, uploads and presents.
- Open for the design: the window must be transparent on this path (decided at window creation, as on Linux); a clip for scrolled native mode; fractional scaling (the probe ran at 100%); several sessions and hidden tabs; device loss and the fallback to the canvas.
